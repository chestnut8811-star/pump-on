# Pump On !（CPB英会話シミュレーター）

心臓手術の人工心肺（CPB）業務に携わる臨床工学技士のための、英会話トレーニング Web アプリ（PWA）です。
外科医・麻酔科医・看護師と交わす英語を、手術の流れに沿って **聞く → 選ぶ → 話す → 流れの中で会話する** の順に練習します。
iPhone では Safari で開いて「ホーム画面に追加」すると、アイコンから全画面・オフラインで使えます。

公開 URL: https://chestnut8811-star.github.io/pump-on/

> 教材は **AI 下書き・臨床未監修** です。会話とモニターの数値はすべて例で、症例は架空です。
> 実際の人工心肺の管理は、施設のプロトコルと担当医の指示に従ってください。

## できること

| 機能 | 内容 |
|---|---|
| 学ぶ | 手術の流れ12シーン＋トラブル6シーン＋基本。シーンごとに解説・フレーズ（簡単／自然／短縮の言い方の幅、返答、聞き取りポイント、施設差・地域差・要確認の注記）・会話（通して聞く／自分の役を演じる）・ドリル |
| ドリル | 聞いて意味／状況から英語／数値の聞き取り／指示への復唱／短縮形の意味／会話の並べ替え／発話（録音・キーボード音声入力・音声認識） |
| CPBシミュレーター | 症例を通しで進め、人工心肺コンソール風のモニターを見ながら相手の英語に応答。ガイド／スタンダード／リアルOR（音声のみ・制限時間）の3モード。振り返りでランクと見直す表現 |
| 数値キャッチ | 流量・圧・ACT・温度・時刻などを現場の読み方（four-eighty、nine forty-two など）で聞き取るミニゲーム |
| 復習 | 間違えた・出会った表現を間隔反復で再出題 |
| 記録 | レベル・XP・連続日数・カレンダー・シーンの習熟度・バッジ。学習記録の書き出し／読み込み |

## 使い方（iPhone）

1. Safari で公開 URL（https://chestnut8811-star.github.io/pump-on/）を開く
2. 共有ボタン（または「…」→ 共有）→「ホーム画面に追加」（「ウェブアプリとして開く」はオンのまま）
3. ホーム画面のアイコンから起動。**追加した直後の初回だけはネットにつないだ状態で開く**（ホーム画面アプリは Safari と保存領域が別のため）。2回目以降はオフラインでも動作
4. 学習記録は端末の中だけに保存されます。機種変更や念のための退避は「記録 → 設定 → 学習記録を書き出す」

音が出ないときは消音スイッチ（消音モード）と音量を確認してください。発話練習は「録音して聞き比べ」が基本です。
「入力」方式ではキーボードを英語にしてマイクキーで話すと自動判定できます。音声認識は試験的機能（設定でオン）です。

## 開発

```
app/          Vite + React 19 + TypeScript 5.9 + Tailwind CSS 4 + vite-plugin-pwa
  src/content/  教材データ（phases・phrases・dialogues・cases・glossary・sources）
  src/engine/   読み上げ・照合・復習間隔・ドリル生成・シミュレーター進行など
  src/screens/  画面
  tests/        教材の整合性テストとエンジンの単体テスト
docs/         要件定義・設計・執筆ルール・調査（根拠）・監修用一覧
design/icon/  アイコン（Codex で生成した候補と採用版）
```

よく使うコマンド（`app/` で実行。node は `/usr/local/bin/node` を使う）:

```bash
npm run dev           # 開発サーバ（http://127.0.0.1:5173）
npm run check         # 型チェック＋lint＋テスト＋ビルド
npm run preview       # ビルド結果の確認（http://127.0.0.1:4173）
npm run review-sheet  # 監修用一覧 docs/review/content-review.csv（Excel で開ける）を書き出す
```

- このフォルダは iCloud 同期下にあるため、`node_modules` は `node_modules.nosync`（同期されない名前）へのリンクです。`npm install` のあとに `bash scripts/fix-nosync.sh` を実行してください。
- 教材の書き方は [docs/content-guidelines.md](docs/content-guidelines.md)。教材を直したら `npm test` で整合性を確認します。

## 監修の流れ

1. `npm run review-sheet` で一覧を書き出す
2. 監修者が CSV の「判定」「監修コメント」欄に記入
3. 確定した項目だけ、教材ファイルの `status` を `'reviewed'` に変更（アプリでは「監修済み」と表示）
